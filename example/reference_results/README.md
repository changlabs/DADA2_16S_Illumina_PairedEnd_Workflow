# Reference results

These are curated outputs from `Rscript example/run_example.R`, generated on 29 September 2026 with R 4.5.2, DADA2 1.36.0, FastQC 0.12.1, MultiQC 1.35, Cutadapt 5.2, FastTree 2.2.0, PICRUSt2 2.6.3, SILVA 138.2, and GTDB r220. These database versions describe the historical outputs accurately. The current setup and future example runs use SILVA 144 and SBDI-GTDB R11-RS232-1; the reports were not rerun for that setup-only update. The supplied Step 4 workbook represents the interactive parameter-selection handoff used by Step 5.

The `reports/` HTML files provide the easiest way to browse all nine workflow steps. Steps 1–3 and 5–9 are rendered execution reports from the bundled example; Step 4 is the rendered Parameter Explorer guide, accompanied by the validated parameter workbook used by Step 5. The step folders contain compact analytical deliverables: the integrity workbook; FastQC statistics and combined MultiQC report; the primer-trimming workbook; the Step 4 parameter workbook; ASV, SILVA and GTDB taxonomy, processing-summary, quality-profile, error-model, and amplicon-length outputs; the multiple-sequence alignment and taxonomy-labelled phylogenetic trees for both databases; PICRUSt2 copy-number predictions and the corrected abundance table; the synthetic-cell-count QMP table; and final tree-bearing SILVA and GTDB phyloseq objects for raw, copy-number-corrected, and microbial-load-corrected abundances.

The cell-count inputs are synthetic test values, not measurements from the source study. They must not be used for biological interpretation. See [`../data/cell_count/README.md`](../data/cell_count/README.md) for their range, assumptions, mock-community placeholder, and supporting references.

Large or repetitive reproducible intermediates are intentionally omitted: the 40 individual FastQC pages, primer-trimmed and filtered FASTQs, checkpoints, PICRUSt2 placement files, console logs, and interactive barplot dependency folders. Links to bundled outputs and tracked workflow source files remain clickable in the executed reports; omitted runtime targets are displayed as annotated plain text instead of broken links. Rerunning the example writes the complete output tree to the ignored `example/run_results/` directory and does not change these reference results automatically.
